System Design: Google Meet PrototypeThis document defines the architectural and user experience design for a localized real-time video conferencing application. The design focuses on high performance for small groups (2–4 users) using a Mesh Network Topology to eliminate server-side media processing costs.1. System ArchitectureThe application is composed of three main layers: the Client Application, the Signaling Server, and the Network Traversal (ICE) Infrastructure.High-Level Component InteractionFrontend (Next.js/React): Manages the UI state, local media streams, and peer-to-peer (P2P) connections using the RTCPeerConnection API.Signaling Server (Node.js/Socket.io): A lightweight WebSocket server that maps socket IDs to meeting rooms and relays negotiation metadata (SDP) and ICE candidates.ICE Infrastructure (STUN/TURN): Discovers public IP addresses (STUN) and provides a relay fallback (TURN) for users behind symmetric NATs or restrictive firewalls.2. UI/UX Design ConceptsThe user experience is divided into three distinct phases to mimic the standard Google Meet workflow.A. The Pre-Call LobbyBefore joining a room, users enter a "Lobby" state.Camera/Mic Preview: Displays the local MediaStream so users can check their appearance.Device Toggles: UI buttons to mute the microphone or disable the camera before entering the meeting.Join Button: Triggers the signaling process to join a specific meetingId.B. The Meeting GridThe main meeting interface uses a dynamic grid system to display participant tiles.Responsive Grid: Utilizes CSS Grid with grid-template-columns: repeat(auto-fit, minmax(300px, 1fr)) to automatically resize video tiles as participants join or leave.Self-View: A small, floating or pinned tile for the user's own video to save screen real estate for remote participants.Participant Management: For every new participant detected via the signaling server, a new RTCPeerConnection is instantiated and a corresponding <video> element is added to the DOM.C. The Control BarA persistent bottom bar providing essential meeting controls:Media Toggles: Real-time muting/unmuting of local audio and video tracks.Screen Share: Triggers getDisplayMedia() to capture the screen and swap it with the camera track.End Call: Closes the RTCPeerConnection, stops all media tracks, and redirects the user back to the home page.3. Data Models & Signaling ProtocolThe signaling server maintains minimal state to remain performant and scalable.Room/Peer MappingThe server tracks active sessions using simple in-memory maps (or Redis for production):Rooms Map: Map<RoomId, Set<SocketId>> — Stores which users are currently in which meeting.Socket-to-Room Map: Map<SocketId, RoomId> — Quickly identifies which room to notify when a user disconnects.Signaling Event SchemaCommunication between the client and server follows a strict event-based protocol:Event NameData PayloadPurposejoin-room{ roomId, userId }User requests to enter a specific room.user-connected{ userId }Broadcast to existing members that a new peer has arrived.offer{ to, from, sdp }Relays an SDP offer from the caller to the callee.answer{ to, from, sdp }Relays the SDP response from the callee back to the caller.ice-candidate{ to, from, candidate }Exchanges network paths for P2P connection testing.user-disconnected{ userId }Notifies peers to remove the video tile of the departed user.4. Technical SpecificationsTopology: Mesh (Direct P2P).Security: Mandatory HTTPS for browser media access; WSS for encrypted signaling; SRTP/DTLS for encrypted media data.Codecs: Opus (Audio) and VP8/H.264 (Video) for maximum browser compatibility.Constraints: Default video resolution of 720p (1280x720) at 30fps to balance quality and bandwidth.5. Network Traversal StrategyTo ensure a ~100% connection success rate, the design incorporates a multi-step ICE gathering process:Host Candidates: Attempt a direct connection via local IP (only works on the same network).Server Reflexive (STUN): Discovery of public IP via stun.l.google.com:19302.Relay (TURN): Fallback to Metered Video or a self-hosted Coturn server if direct P2P is blocked.
